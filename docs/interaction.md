# 首版交互方案

用户已确认需要终端界面、单项启停与日志、全部启动和退出时全部停止。以下入口、键位和布局是实现提案，待真实试用调整；不是当前 CLI 已支持的功能清单。

## 1. 进入与退出

拟定入口：`devctl --config /path/to/devctl.toml run`，启动配置中的默认项目组合并进入终端界面。保留现有 `run <service>` 单项前台入口，避免破坏已有用法；新增入口行为以实际实现与帮助为准。

正常流程：一次进入 → 三项运行 → 选择项目看日志或单独启停 → 退出时全部停止。不保存上次选择，下次按配置重新启动。`validate` 和 `plan` 继续只读，不执行命令。

## 2. 界面与操作

```text
项目                 日志：web
> web       运行中   [stdout] ...
  weapp     运行中   [stderr] ...
  middle    已停止

↑/↓ 选择  s 启动  x 停止  a 全部启动  X 全部停止  q 退出
```

- 左侧列出项目名称与状态；右侧显示选中项目的近期日志，支持基本滚动与回到底部。
- `s/x` 只作用于选中项目；`a/X` 作用于当前工作区。停止全部后界面保持打开，可重新启动。
- `q` 或 Ctrl-C 结束整个前台会话；显示清理进度，全部停止后恢复终端并退出。
- 已运行项目重复启动不创建新进程；停止中的项目先完成清理才能再次启动。
- 失败显示项目名和原因；其他项目继续运行，可由用户重新启动失败项目。
- 显示“运行中”只表示进程存活，不承诺编译成功或业务就绪。

当前每个项目配置一个开发命令。沿用配置中的 Project/Service 表达方式；多服务项目的聚合界面不在本轮展开，不能静默只操作其中一个服务。

## 3. 实现时验证

窄窗口仍能看到当前项目、状态及操作帮助；日志高输出时键盘与退出可响应；终端恢复覆盖正常退出、信号和可处理错误。无 TTY 的批量入口行为须在实现时明确，不强行进入 raw mode。
