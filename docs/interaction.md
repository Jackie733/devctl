# 首版交互方案

已确认：TUI、单项与全部启停、按项目日志、后台运行；默认离开界面后服务继续运行，结束开发时显式全部停止。2026-10-14 用户确认首版采用左右分栏：左侧项目列表，右侧选中项目日志，底部操作与连接反馈。后台控制和 TUI 已实现；受控验证与真实项目试用进度见 [任务记录](tasks.md)。

## 1. 启动与连接

所有需要工作区的命令（包括 validate、plan、tui 与后台控制）统一按以下顺序选择配置，第一个存在的配置生效，不合并：

1. 显式 `--config PATH`。
2. 当前目录的 `devctl.toml`，兼容原有用法。
3. `~/devctl.toml`。
4. `~/.config/devctl/devctl.toml`。

后两项基于 HOME 查找。找不到时列出查找位置并报错，不创建文件；高优先级位置是目录/无效符号链接或路径检查失败时直接报错。发现只选择路径，各命令仍沿用原有加载规则：需要读取时，解析或读取失败不回退到其他工作区；连接已有后台不重载磁盘配置。帮助、版本及无参数帮助不要求配置。

配置在默认位置时可直接执行 `devctl validate`、`devctl tui` 等短命令；需要固定工作区时，仍可给下列命令加上 `--config /path/to/devctl.toml`：

| 命令 | 行为 |
| --- | --- |
| `devctl tui` | 连接或创建后台管理实例，显示界面，不自动启动服务 |
| `devctl start web` | 只启动 web，其他项目保持原状态；需要时创建后台管理实例 |
| `devctl start weapp` / `devctl start middle` | 分别只启动小程序或中台 |
| `devctl start --all` | 启动默认组合，已运行项目不重复启动 |
| `devctl stop web` | 停止 web，其他项目保持原状态 |
| `devctl stop --all` | 停止所有项目，后台管理实例保留，可重新启动 |
| `devctl logs web --limit 100` | 读取 web 的近期日志快照，区分 stdout/stderr 与运行实例，不创建后台 |
| `devctl status` | 查询已有后台的服务状态及失败原因，不创建实例 |
| `devctl shutdown` | 停止全部托管进程并结束后台管理实例 |

本场景项目与服务 ID 相同，一项目一个命令；上述目标参数沿用 Service ID，未来扩展多服务项目时显式增加项目选择参数，不混用两类 ID。

`start` 返回请求是否受理，不能把受理称为业务就绪；`stop` 和 `shutdown` 需明确报告清理成功或失败。再次打开 TUI 连接已有实例，不依据默认配置重新启动已被用户停止的项目。`stop`、`shutdown` 在后台不存在时不创建新实例。

配置中的 `autostart = true` 表示该服务属于 `a` / `start --all` 的默认启动组合，不表示进入 TUI 就执行启动命令。进入界面后可按 `a` 启动该组合，也可以先执行 `devctl start --all` 再执行 `devctl tui`。

现有前台命令为 `run <service>...` 或 `run --all`。前者至少显式选择一项，重复 ID 只启动一次；后者选择配置中 `autostart = true` 的默认组合，不可同时传入显式 ID，默认组合为空时显示无服务被选择并成功退出。整批选择先校验，未知 ID 或未支持的依赖在任何服务启动前拒绝；某项启动失败或意外退出立即显示原因，其他项继续运行。Ctrl-C/SIGTERM 清理所选服务；全部自然结束或显式停止后退出，本轮有失败则退出码为 1，否则为 0。

前台模式已使用配置运行锁，同一配置的第二个运行者会在启动任何服务前报错。后台复用同一锁，前后台不能同时托管同一工作区。`validate` 和 `plan` 继续只读。

日志快照可通过 `--after <序号>` 读取后续记录；输出中的 `#实例` 和 `seq=序号` 用于区分运行轮次和分页位置。结束并重建后台后旧游标失效。截断、丢弃、缓存缺口和读取不完整会明确提示；预算和传输规则见 [DESIGN.md](../DESIGN.md) §5。

停止或结束工作区无法确认清理时返回错误，后台保留运行锁与失败原因供查询，避免再次托管同一配置。该状态不自动恢复，不宣称工作区已经结束。

## 2. 界面与操作

```text
项目                 日志：web
> web       运行中   [stdout] ...
  weapp     运行中   [stderr] ...
  middle    已停止

↑/↓ 选择  s 启动  x 停止  a 全部启动  X 全部停止  q 离开
```

- 左侧选择项目，右侧显示近期日志，支持基本滚动与回到底部；从全部停止状态可以只启动任意一个项目。
- `s/x` 只操作选中项目；`a/X` 操作工作区。停止全部后保留界面与后台，可重新启动。
- `q` 或 Ctrl-C 离开客户端并恢复终端，后台及项目继续运行；关闭客户端终端或客户端断开也不停止服务。
- `Q` 打开“结束工作区”确认框，`y` 确认，`n/Esc` 取消；确认成功后清理全部项目、结束后台并离开界面。框内的 `q` 或 Ctrl-C 仍只离开界面。
- `PageUp/PageDown` 滚动日志，`Home` 查看本地缓存最旧记录，`End` 恢复底部跟随，`Left/Right` 横向查看长行；切换项目重新读取后台近期输出。日志一条记录占一行，超宽部分通过水平滚动查看。
- `?` 查看帮助，`?/Esc` 关闭帮助；`r` 重新同步现存后台。控制操作等待期间不排队新操作，但可选择、滚动和离开。
- 已运行项目重复启动不创建新进程；停止中的项目先清理，再允许启动。
- 失败显示项目名和原因，其他项目继续运行；“运行中”仅表示进程存活，不承诺编译成功或业务就绪。

多服务项目聚合界面待确认，当前不静默只操作一个服务。键位可在试用时调整，但离开与停止的语义不混用。

宽窗口显示左右分栏；较窄窗口将项目列表收起，保留当前项目、状态、日志与紧凑键位，仍用上下键切换；极小窗口只显示必要状态与离开提示。无 TTY 时明确报错，可使用控制 CLI。

进入 TUI 后直接显示项目管理界面与连接反馈，不播放启动动画。

## 3. 断开与异常

后台连接断开时界面显示“已断开，状态未知”，不把缓存当作仍在运行的证据；重连从后台取得当前状态与近期日志。自动轮询和 `r` 只连接现存后台，不自动创建或重放启停；若后台已结束，可离开后重新进入创建空闲实例，或由其他 CLI 启动后等待重连。慢客户端或无客户端时后台仍持续读取输出，日志有界。

后台管理进程的停止信号触发进程清理；客户端的退出信号只恢复终端并断开。后台异常退出、机器重启后的恢复另行确认，不凭旧 PID 自动接管进程。
