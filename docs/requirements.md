# devctl 需求提案

状态：规划，尚未实现。调研日期：2026-10-09。

## 1. 定位与目标

面向同时开发多个仓库、多个本地服务的开发者。工作区是一组项目目录、服务定义和依赖关系，可以存放在任意目录，不要求项目属于同一个 Git 仓库或 Cargo workspace。

核心体验：在一个终端启动一套开发环境，知道哪些服务正在运行、哪些在等待、为什么启动失败；结束工作后可以恢复同一套服务选择。

主要价值应放在跨仓库组织、明确的生命周期语义、可解释的失败和可靠恢复。TUI 是操作入口，编排能力独立于 TUI。

初始假设：单用户、本机、可信配置、约 5–20 个服务；优先 Linux 和 WSL2 内的 Linux 进程。规模数字是设计目标，需要基准验证。

## 2. 领域术语

| 概念 | 定义 |
| --- | --- |
| Workspace | 开发上下文，包含项目、服务、配置位置和会话信息 |
| Project | 本地目录引用，不要求是 Git 仓库；项目操作聚合其服务，目录本身不启动 |
| Service | 长期运行的命令，如数据库、API、前端、worker |
| Task | 执行后退出的一次性命令，如迁移；P1 引入 |
| Dependency | 服务启动前必须满足的条件，MVP 支持 `started`、`ready` |
| Readiness | 本轮启动是否已满足配置的就绪条件，区别于进程存活 |
| Session | 用户希望启动的服务集合、工作区和界面选择 |
| Supervisor | 管理状态、依赖调度和生命周期的组件；不等同于后台守护进程 |

## 3. 需求优先级

P0 是首个可日常使用版本必须完成的闭环；P1 是后续增强；P2 是待真实需求验证的能力。

| 编号 | 需求 | 级别 | 可观察的验收结果 |
| --- | --- | --- | --- |
| W01 | TOML 配置引用任意本地项目目录 | P0 | 配置放在第三个目录，仍可启动两个不同仓库的服务 |
| W02 | 绝对路径、相对路径、路径中的空格 | P0 | 相对路径以配置文件目录解析，不受调用目录影响 |
| W03 | 配置校验与启动计划 | P0 | 缺失目录、未知字段、无效命令、依赖环在启动前报错 |
| P01 | 启动、停止、单服务重启 | P0 | 停止完成后再启动新实例，重复启动不产生第二实例 |
| P07 | 项目与工作区批量控制 | P0 | 可独立启停一个项目，也可启动工作区默认组合；操作范围可见 |
| P02 | 异常退出与启动失败检测 | P0 | 显示退出码或信号、失败原因、发生时间和本轮实例 |
| P03 | 有界自动重启 | P0 | 指数退避、重试上限；用户停止立即取消后续重试 |
| P04 | 优雅退出与超时强制停止 | P0 | 正常退出清理管理范围内的进程组并回收直接子进程 |
| D01 | 依赖图与并行启动 | P0 | DB 就绪才启动 API，API 就绪才启动 web；独立分支并行 |
| D02 | TCP、exec 就绪探针与总超时 | P0 | 超时显示具体阻塞原因，下游保持等待或进入 blocked |
| D03 | 依赖失败隔离 | P0 | 失败分支不阻止无关分支运行，已运行下游显示降级 |
| L01 | 聚合日志、按服务筛选、stdout/stderr 来源 | P0 | 日志行带时间、服务 ID、流类型和实例编号 |
| L02 | 滚动、暂停跟随、文本搜索 | P0 | 暂停仅暂停滚动；服务输出持续被读取 |
| L03 | 有界日志缓冲、超长行和无效 UTF-8 | P0 | 长时间运行内存有上限；截断、丢弃可观察 |
| U01 | 键盘驱动的 TUI | P0 | 工作区/项目/服务树、按范围聚合日志、状态原因、操作帮助 |
| U02 | 非交互前台运行与配置校验 CLI | P0 | 无 TTY 可运行；控制信号触发相同的退出流程 |
| R01 | 恢复最近工作区和服务选择 | P0 | `resume` 重新校验配置，以依赖顺序创建新进程 |
| R02 | 单工作区运行互斥 | P0 | 两个终端同时运行相同配置时，第二个明确报错 |
| X01 | Linux、WSL2 验证 | P0 | 两个平台通过生命周期和依赖集成场景 |
| W04 | 工作区注册、列表、profiles | P1 | 用别名选取工作区和服务组合，移动配置可重新绑定 |
| D04 | HTTP 就绪、一次性任务 `completed_successfully` | P1 | 迁移成功才放行 API，迁移失败不无限重启 |
| D05 | 持续健康检查、显式级联重启 | P1 | 区分启动就绪和运行中不健康；级联范围可预览 |
| L04 | 日志落盘、轮转、历史查询 | P1 | 达到容量限制轮转；磁盘写入失败不堵住子进程 |
| P05 | 后台 supervisor、attach/detach、独立控制命令 | P1 | 关闭 TUI 后进程继续运行，可重新连接 |
| X02 | macOS、Windows 原生支持 | P1 | 分别验证 Unix 停止语义和 Windows Job Object 清理 |
| P06 | 交互式 PTY、输入转发、终端调整大小 | P2 | 可运行交互程序；明确 PTY 无法区分 stdout/stderr |
| W05 | package.json / Procfile 导入、文件变化重启 | P2 | 仅在实际用户需要时加入，保持显式配置可理解 |

## 4. 主要用户流程

### 创建和启动

1. 编写一个 `devctl.toml`，引用数据库、API 和前端所在目录。
2. `devctl --config /path/to/devctl.toml validate` 校验配置。
3. `devctl --config /path/to/devctl.toml plan web` 查看 web 的依赖闭包、探针和执行目录。
4. `devctl --config /path/to/devctl.toml run web` 启动 DB → API → web，打开 TUI。
5. `run` 未指定服务时启动所有 `autostart = true` 的服务及其依赖。

`run --no-tui` 使用同一引擎，将聚合日志输出到终端；没有自动交互提示。

### 日常操作

- `devctl tui` 进入工作区管理界面，不自动启动服务；选中工作区、项目或服务后执行操作。详细流程见[交互设计](interaction.md)。
- 项目启动聚合该项目 `autostart = true` 的服务；其他服务可展开单独操作。项目停止涵盖该项目所有托管服务，并取消该范围的等待和重试。
- 工作区启动使用默认组合及其依赖；停止覆盖当前工作区所有托管服务；重启保留当前期望运行的服务集合。
- 选择服务可查看命令、工作目录、当前状态、就绪状态、重试次数和错误原因。
- 启动一个服务自动加入它的传递依赖；启动已运行服务是幂等操作。
- 手动重启默认仅重启目标，下游保留运行并显示依赖降级；新实例重新通过就绪检查后解除降级。
- 手动停止默认仅停止选中范围；范围外下游保留运行并显示降级，等待中的下游显示阻塞，不自动拉起被手动停止的依赖。显式级联停止才加入活动或期望运行的传递下游，并按逆依赖顺序停止。
- `q` 结束前台会话，按逆依赖顺序停止所有托管服务并恢复终端。P0 没有 detach。

### 异常与恢复

- API 异常退出：记录原因；按策略退避重启；等待 API 的 web 不提前启动；已运行的 web 显示降级。
- DB 就绪超时：停止本轮 DB，重试仍受预算约束；DB 最终失败后 API、web 显示依赖阻塞链。
- `devctl resume` 使用最近工作区；`--config ... resume` 恢复指定工作区的最近服务选择。
- 正常退出保存退出前希望运行的服务，不把退出清理动作记录成用户清空会话。
- 恢复只重建进程和服务组合，不恢复数据库内容、内存、shell 或之前的 PID。

## 5. 关键语义与边界

1. 进程启动不代表业务可用。`ready` 依赖的目标必须配置就绪探针，省略时校验失败。
2. MVP readiness 只负责每轮启动的门槛；不承诺持续健康监测。TCP 连通只能证明端口可连接，数据库应优先使用 `pg_isready` 等业务探针。
3. 长期服务未被要求停止却退出，即使退出码是 0，也属于意外退出；`on-failure` 按此语义重试。一次性任务在 P1 单独建模。
4. 自动重启默认关闭。启用后有最大重试次数；成功稳定运行达到窗口后才重置预算。
5. 终止针对本轮拥有的进程组。主动脱离进程组的 daemon、外部容器和机器上已运行的服务不属于 MVP 托管范围。
6. 项目可以属于多个工作区，但 MVP 不共享进程实例。端口冲突展示真实错误，不自动杀死或接管其他程序。
7. 工作区配置只描述运行方式；devctl 不自动拉取代码、切换分支、安装运行时或准备数据库数据目录。
8. 所有配置和会话读取都不执行服务命令；只有显式启动或恢复才执行。就绪 exec 使用和服务一致的执行上下文。

## 6. 非功能目标

以下是拟定的验收预算，不是现有性能承诺。使用固定测试机器、终端和可复现输出负载，记录基线。

| 项目 | 初始目标 |
| --- | --- |
| 正确性 | 直接子进程退出始终被回收；正常退出后测试进程组不残留 |
| 可响应性 | 20 个服务、总计 2,000 行/秒时，键盘操作反馈 P95 小于 100 ms |
| 内存 | 日志文本缓冲每服务 2 MiB、全局 32 MiB；索引和队列也有显式上限 |
| 长行 | 单条显示记录最大 16 KiB，继续读取并记录截断数量 |
| 重绘 | 有变化才重绘，刷新上限 30 FPS，状态事件不按帧率延迟调度 |
| 错误信息 | 每个阻塞服务展示依赖链，每次进程失败保留阶段和错误类型 |
| 隐私 | 会话状态不保存环境变量值；工具内部 tracing 与服务日志分开 |
| 兼容性 | 配置带版本，未知版本拒绝；发布时声明并验证 Rust MSRV |

日志和配置可能包含开发者主动写入的敏感内容，不能宣称自动脱敏覆盖全部情况。界面默认不展示环境变量值，会话只保存引用和服务 ID。

## 7. 首版发布验收

| 场景 | 必须满足 |
| --- | --- |
| 三个项目位于不同目录 | 任意调用目录启动结果一致，路径带空格仍正确 |
| DB 延迟就绪 | API 尚未 spawn；DB 探针成功后 API 才启动 |
| 依赖环 / 不存在的服务 | 在任何服务启动前报错，展示环路径或缺失 ID |
| API 连续崩溃 | 退避符合配置，达到上限后 failed，无限重启不会发生 |
| 退避期间用户停止 | 后续计时器和旧探针结果不能再次启动服务 |
| spawn 一个会派生子进程的服务 | 停止和超时强杀后测试进程组被清理，直接子进程已 wait |
| DB 失败，同时独立 worker 正常 | worker 继续运行，API/web 展示阻塞链 |
| 海量输出、无换行、坏编码 | 内存缓冲有界，TUI 可操作，丢弃和截断有提示 |
| 重启后旧输出、旧探针迟到 | 不把旧实例就绪/退出事件应用到新实例 |
| 正常退出 / Ctrl-C / 可恢复 panic | 停止流程执行且 raw mode、光标和 alternate screen 恢复 |
| 强制杀死 devctl 后再启动 | 不凭旧 PID 宣称服务在运行；明确异常会话和残留限制 |
| 两个终端同时启动同一配置 | 仅一个持有运行锁；不产生两套服务 |
| 独立停止前端项目 | 前端项目内服务停止，API/DB 继续运行 |
| 独立停止 API 项目 | API 停止，前端仍运行并显示依赖降级；API 不被自动重新启动 |
| 级联停止 API 项目 | 前端先停止，再停止 API，DB 保留；等待/退避中的下游也取消 |
| 工作区启动/停止/重启 | 默认组合按依赖启动；全部停止；重启不启用用户原先手动关闭的服务 |
| 保存中断 / 状态损坏 / 项目移动 | 可读的错误或回退；不执行失效配置，不破坏原状态 |

## 8. 暂不纳入

生产部署、分布式调度、远程 SSH 编排、IDE、Git 工作流、依赖安装器、容器运行时、插件系统、嵌入脚本语言、完整终端模拟器。后续需求通过实际场景进入路线，不为可能的需求提前做抽象。
