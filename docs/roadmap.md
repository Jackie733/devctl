# 实施路线

主线：三个项目的统一终端管理。范围以 [requirements.md](requirements.md) 为准，每个当前小步记录在 [tasks.md](tasks.md)。2026-10-10 已根据真实场景收缩原规划，后台运行随后已由用户确认纳入首版；用户已确认其他扩展在 MVP 完成并试用后再评估，见需求文档 §4。

## 1. 首版阶段

| 阶段 | 交付物 | 完成标准 | 需求 |
| --- | --- | --- | --- |
| M1 配置 | 项目目录、命令、路径解析与校验 | 三个项目可表达；从任意目录校验；无效配置不启动进程 | W01–W03 |
| M2 单项生命周期 | 启动、信号停止、进程组清理与退出报告 | 派生后代被清理；忽略 TERM 时超时强杀；退出可解释 | P01、P02、P04 |
| M3 多项目管理 | 并发运行、单项与全部控制、运行锁 | 可只启动一项或全部；单项停止互不影响；关闭管理器时全部清理 | P01、P07、P04、R02 |
| M4 后台管理 | 独立 supervisor、本地控制通道、实例发现与后台日志读取 | 关闭客户端终端服务继续运行；重连原实例；并发启动不重复创建；无客户端日志有界 | P05、R02、P04、L01、L03 |
| M5 终端界面与日志 | 连接后台、项目列表、状态、日志与操作键 | 单项/全部控制；离开不停止；结束工作区全部清理；终端恢复 | U01、P01、P07、P05、L01、L03 |
| M6 真实项目试用 | web、小程序、中台完整流程 | 用户完成单项、全部、后台、重连和停止验收 | X01、首版全部需求 |

## 2. 推进规则

- 每步必须关联上述需求，并说明它改善哪个已确认场景；必要的进程和日志安全边界也要关联到对应验收。
- 已有配置与计划代码继续保留，不把已有代码等同于整个阶段已验收。
- 当前 M3/M4 的后台控制、独立生命周期、身份握手与有界日志代码已完成受控验证；按用户要求停在 M5 的 TUI 实现前。完整操作体验与真实 npm/pnpm 流程仍待 M5/M6 验收。
- M3 可用简短文本反馈验收控制行为，M4 将管理循环放入独立后台进程，M5 接入已验证的控制接口；不把 TUI 降为可选的首版外功能。
- 产品行为或首版范围变化先与用户核对；局部 Rust 实现由助手按最小可维护方案推进。
- M1–M6 的首版验收完成后，再结合用户试用反馈评估需求文档 §4；此前不展开扩展设计或为其预建抽象。

## 3. 按需学习

M2/M3 学习 Child 所有权、异步等待、信号和任务回收；M4 学习进程间通信与后台生命周期，M5 再学习终端事件、界面状态与渲染分离。每步只解释当前代码涉及的 Rust 概念，不要求提前引入完整引擎接口或阅读所有参考项目。
