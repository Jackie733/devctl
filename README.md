# devctl

Rust 原生开发工作区管理器：用一个工作区组织分散在不同目录中的项目，按就绪依赖启动服务，统一观察进程和日志，并恢复上次的开发会话。

当前仓库正在逐步实现配置校验、依赖计划与单服务运行。实际验收进度见[开发与学习任务记录](docs/tasks.md)；下列规划文档描述目标能力，不代表全部已经实现。

## 项目规划

- [协作与 Rust 教学规范](AGENTS.md)：逐步审查、测试、提交与誊写学习流程。
- [开发与学习任务记录](docs/tasks.md)：实际进度、验证证据与下一步。
- [需求与验收标准](docs/requirements.md)：产品边界、优先级和验收标准。
- [交互流程](docs/interaction.md)：工作区、项目、服务三层操作，独立启停与依赖影响。
- [技术架构](DESIGN.md)：系统模型、状态与并发、进程管理、依赖编排、日志、恢复和跨平台策略。
- [实施路线](docs/roadmap.md)：阶段顺序、需求映射与按需学习入口。

建议先阅读需求，再按实施路线完成“跨目录配置 → 可靠进程生命周期 → 就绪依赖 → 聚合日志与 TUI → 会话恢复”的闭环。
